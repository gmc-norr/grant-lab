# Code Review — Defects Report

## Executive Summary

- **The core security model is sound, but the safety/cost-control rails leak.** IDOR scoping, CSRF, argon2 email-enumeration defense, SSRF IP-pinning (on extraction), DOI/XML injection, and the propose-only citation-mutation exclusion are all confirmed correct. The recurring failure pattern is **cost and budget integrity**: hosted-Opus spend escapes its caps in at least five independent ways (failed-turn tokens uncounted, background queues excluded from the global cap, DB-commit-failure re-bills, member-triggerable fan-outs, deep-check unbounded fan-out).
- **Operational resilience has two genuine "silent brick" defects.** A failed setup job strands a workspace in `setup` forever with no recovery path, and the consecutive-failure ingestion alerter is in-memory so a crash-looping outage never alerts — both defeat the exact safety nets they were written to provide.
- **The single-instance constraint is enforced by tribal knowledge, not code.** A one-line horizontal-scale op silently double-runs every job (duplicate digests, duplicate spend). This is the highest-leverage hardening fix in the report.
- **Frontend has three confirmed data-loss/data-bleed bugs on normal paths** — undo-after-section-switch corruption, silent discard of unsaved buffers on tab switch, and cross-workspace chat/stream bleed when navigating mid-turn. These are real recurring work-loss for a drafting tool.
- **Performance debt is mostly latent-but-real:** an unbounded drafting-subprocess pool can exhaust the DB connection pool app-wide (the one High here), plus a cluster of N+1 / no-batch / no-compression / no-code-split issues that are tolerable at hospital scale today but were repeatedly flagged.
- **Several findings are honest non-issues or documentation drift** (the argon2 domain-timing oracle leaks an already-public allowlist; multiple stale "not wired up" comments). These are recorded for completeness but should not be treated as urgent.

## High

- **Unbounded drafting subprocesses exhaust the DB connection pool app-wide** — `proposal_assist/drafting/registry.py:49` (also `controller.py:116`, `db/session.py:15`) — each live drafting subprocess holds one checked-out pooled connection (for its advisory lock) for up to 600s, and nothing caps concurrent subprocesses, so ~30 active workspaces consume the entire `pool_size=10 + max_overflow=20` pool and stall every web request and scheduler tick. *Fix:* bound live subprocesses (semaphore / LRU-evict in `claim_launch_or_wait`) and/or give the advisory-lock sessions a dedicated small pool separate from the request pool. (confirmed)

- **A failed Phase-0 setup job permanently bricks the workspace** — `proposal_assist/phases/setup.py:183-190` — a setup job that exhausts 5 attempts goes `status='failed'`, which never reaches `waiting_for_rubric_review`, so `current_phase` stays `setup` forever and `gate_cloud_llm` 409s every turn/coherence/evaluator/review with no operator or owner remediation short of DB surgery (`requeue_stuck_setup_jobs` only touches `running` rows). *Fix:* add an owner/admin re-queue endpoint that resets a `failed` setup job and surface the failed-setup state in the read-model. (confirmed)

- **In-memory consecutive-failure alerter never fires across restarts** — `ingestion/alerts.py:20-90` — the 3-strike streak lives in a process-local dict, so any deploy/OOM/crash within the 3-day window resets it to 0; a reliably-broken source whose host restarts more than every ~3 days (normal for a process also spawning LLM subprocesses) stays broken indefinitely and the admin alert never sends. *Fix:* persist failure streaks on `Source` (transactional with `last_fetched_at`), and add a restart-independent "last_fetched_at older than N days" backstop. (confirmed)

- **Single-instance constraint is convention-only; a second replica silently double-runs every job** — `scheduler.py:83-94` — there is no advisory lock, leader election, or startup guard, so a routine horizontal scale-out causes duplicate digest emails to all users, duplicate Anthropic spend, racing writes, and split failure-tracking, with nothing logging or refusing. *Fix:* acquire `pg_try_advisory_lock(hashtext('call-manager-scheduler'))` in `lifespan` before `sched.start()`; if not held, build with `start=False` and log loudly (the docstring already names this primitive). (confirmed)

- **Analysis job re-spends all tokens on every retry and dead-letters a whole section on one bad local verdict** — `proposal_assist/analysis/pipeline.py:338-340` (+121-131, 205-236, 510-533) — `analyze_job` only `flush()`es classifications (commit is post-return), so any mid-loop exception rolls back all partial work and re-runs the full cited+uncited LLM loop on retry, re-spending tokens; separately, `if any(... 'audit_unavailable')` treats a *single* malformed/empty Gemma verdict as a hard failure, so 3 such retries permanently dead-letter the section. *Fix:* commit classification progress before the verdict phase, and only re-raise on the cap signal (degrade-and-continue on a transient/invalid row). (confirmed)

- **Literal `[@token]` in prose permanently hard-blocks all composed export** — `proposal_assist/citations/bibliography.py:716-728` (`_BARE_MARKER_RE` at `:36`) — `compose_export`'s fail-closed residual scrub runs `_BARE_MARKER_RE` over the whole document with no code-fence awareness, so a verbatim `[@smith2021]` in a code block or methods example raises `BuildBibliographyBlocked` on every export, bricking the whole document with no clear fix. *Fix:* make the residual scrub fence/code-span aware (mirror `iter_proposal_sentences`' fence tracking) or scope it to spans `find_markers` would have matched. (confirmed)

- **Admin digest re-enable doesn't reset the bounce counter — user re-disabled on the next single bounce** — `web/api/admin.py:408` (+`digest/send.py:173-185`) — `admin_reenable_user` clears `digest_disabled_at` but leaves `digest_bounce_count` at 3, so the next bounce hits 4 (`>= 3`) and immediately re-disables, making the admin action effectively cosmetic for any flaky-but-recovering mailbox. *Fix:* also set `digest_bounce_count = 0` on re-enable, and surface the count in the disabled-users list. (confirmed)

- **Ctrl+Z after a section switch corrupts the active section with the previous section's text** — `frontend/src/editor/CodeMirrorEditor.tsx:225-235` — the controlled value-push dispatches a full-doc replace tagged `Transaction.remote` but **not** `addToHistory.of(false)`, so CM6 records the swap as undoable; undo after switching A→B reverts the doc to A's text as a *local* change, which the updateListener writes into B's buffer and marks dirty — silently overwriting B's content, which can then be saved. *Fix:* add `Transaction.addToHistory.of(false)` to the push and clear history on a full-doc swap. (confirmed)

(confirmed)

- **CockpitChat streams the wrong workspace and bleeds chat when navigating between cockpits mid-turn** — `frontend/src/cockpit/chat/CockpitChat.tsx:29-39,61-66`; `shell/AppShell.tsx:44`; `router.tsx:42` — the right pane is rendered with no `key`, so navigating `/cockpit/A → /cockpit/B` reconciles the same CockpitChat instance; `jobId`/`streamed` are set but never cleared on `id` change, so the SSE URL targets `workspaces/B/turns/jobA/stream` and A's leftover streamed turns fold into B's list by position, momentarily showing one proposal's draft under another. *Fix:* key the cockpit subtree by workspace id (remount on change) or reset `jobId/streamed/cancelNote` in a `[id]` effect. (confirmed)

- **must_include substring match drags off-topic calls into paid LLM/escalation** — `ranking/rank_pair.py:334-365` — `_call_matches_must_include` does a raw `term in haystack` test over title+summary+full_text+keywords, so a short term like `ai`/`rna`/`eu` matches inside `training`/`brain`/`queue`, sets `must_include_override=True`, and bypasses both the timeline-fail and embedding-hard-fail gates into Gemma and occasionally a billed Sonnet escalation for every spurious match. *Fix:* match on word/token boundaries (`\b{re.escape(term)}\b`) with a minimum length, kept identical in `rank_pair` and `assemble.py`. (confirmed — listed High for cost/escalation blast radius despite the "Low" source tag; the digest path shares the same false matches)

## Medium

### Cost / budget integrity (hosted Opus) — *5 findings, one theme*

- **Failed-turn tokens are never charged against the daily cap** — `proposal_assist/turns/outcomes.py:78` (+`caps.py:107`, `processor.py:335`) — on failure the user-turn pre-count is unconditionally cleared and consumed tokens are written only to the `WorkspaceEvent` audit payload (which the cap query never reads), so a turn that streamed text and tool calls before failing records *zero* against the cap; a looping user can burn real Anthropic spend indefinitely under the cap. *Fix:* stamp actually-consumed tokens onto a `ChatTurn` row; only clear the pre-count when nothing was consumed. (confirmed)

- **The "global" daily token cap counts only chat turns, excluding coherence/evaluator/review spend** — `proposal_assist/turns/caps.py:103-150` — `check_daily_token_cap` and `check_global_daily_token_cap` sum only `ChatTurn` tokens; the three background queues track spend on their own tables with private caps, so the advertised org-wide runaway-spend backstop never sees ~3/4 of cloud consumers. *Fix:* UNION the three job tables into the global cap query, or document explicitly that the global cap is chat-only. (confirmed)

- **DB-commit failure after a billed Sonnet escalation re-bills on retry** — `ranking/worker.py:208-260` — `rank_pair`'s billed remote call, the ledger row, and the merge/commit share one transaction; if commit raises (deadlock / transient drop — a known-flaky condition here), the ledger row rolls back, the job reverts to PENDING, and the next tick re-runs the full `rank_pair` (fresh paid Sonnet call) up to `MAX_ATTEMPTS=5` times, none counted against the cap. *Fix:* record the remote attempt in its own committed transaction immediately after `rank_pair` returns, or cache the result on the job row for reuse. (confirmed)

- **Non-owner members can trigger the most expensive cloud fan-outs while direct edits are owner-only** — `proposal_assist/web/review.py:143`, `coherence.py:52`, `evaluator.py:53` (also `uncited_claims.py:80`) — `submit_turn` requires owner, but `start_review_run`/`coherence`/`evaluator` gate on `require_member`, so any disclosure-acked collaborator can exhaust the workspace's full daily Opus budget (review = a 6-call Opus fan-out) with no per-actor sub-cap; the asymmetry is undocumented. *Fix:* decide the authority model — restrict to `require_owner` to match turns, or keep member-open but add a per-actor sub-cap. (confirmed; merges with the cross-cutting `xc-security` duplicate of the same issue — **found by 2 lenses**)

- **Deep-check semantic audit is an unbounded, request-blocking LLM fan-out over the whole ledger** — `proposal_assist/citations/audit.py:539-604` (+`web/api/citation_audit.py:135-150`) — `POST /citation-audit/deep` makes one `complete_json` call per uncached evidence row with no per-request ceiling, so a hundreds-citation proposal fires hundreds of sequential synchronous LLM calls in one HTTP thread, draining the daily token budget (starving the background analysis drain) — the only guard is the best-effort, racy daily cap. *Fix:* cap fresh judgements per request (report `checked` vs deferred) and/or move deep-check to the background queue. (confirmed)

### Citation-audit correctness

- **Metadata-approval IntegrityError retry can crash (500) and silently keep a colliding citekey** — `proposal_assist/web/api/references.py:326-341` — after rollback the handler re-fetches and immediately does `ref.csl_json = csl` with no None-check (concurrent delete → AttributeError → 500), does **not** regenerate the citekey on retry (genuine collision keeps the old/unresolved key), and swallows *all* IntegrityErrors so an unrelated constraint re-raises uncaught. *Fix:* guard the re-fetch for None (404), regenerate the citekey only if still colliding, and scope the except to the citekey unique constraint via SQLSTATE. (confirmed)

- **`propose_citation` keys the pending row's section from a raw `.find()` that can disagree with the overlap-aware uniqueness check** — `proposal_assist/tools/citations.py:498-513` — step 5 proves anchor uniqueness via `anchor_occurrences` (skipping marker spans) but step 6 maps the anchor to a section with `read_view.find(anchor)`, so when the proposal already contains markers the row can be keyed to the wrong section, corrupting staleness gating (won't go stale when the real section changes; spuriously goes stale when the mis-keyed one does). *Fix:* use `markers.anchor_occurrences` for the section lookup, as the comment itself mandates. (confirmed)

- **`claim_sentence_around` is not heading-aware — a cite after a heading stores the heading markup as the "claim"** — `proposal_assist/citations/claims.py:24-79` — it walks back only over `.!?\n` with no heading/fence handling, so `## Aims\n[@x]…` yields `'## Aims'`, which becomes the stored claim provenance and the CLAIM fed to the semantic judge — degrading audit quality and the cited-claim annotations users see. *Fix:* stop the backward scan at a `^\s*#` heading boundary. (confirmed)

- **Spurious permanent `claim_drift` for a citation with no preceding prose** — `proposal_assist/citations/audit.py:394-417` vs `tools/citations.py:649-660` — at insert time a marker at document/section start (empty extracted claim) hashes `sha256(normalize(anchor))`, but the validator re-derives the empty claim and hashes `sha256(normalize(''))`, so the hashes never match and the row is reported as drift on every audit forever, blocking "clean audit" states. *Fix:* make insert-time fallback and validator agree (share one hash-basis helper). (confirmed)

### Reference ingestion

- **ZIP decompression guard trusts attacker-forgeable declared sizes and checks no compression ratio** — `proposal_assist/references/extract.py:41-61` — `_guard_zip_bomb` only sums central-directory `info.file_size` (attacker-controlled) against a 200 MB cap, never comparing to `compress_size` or real inflated length, so a crafted `.docx`/`.xlsx` can inflate far past the declared size and OOM the extraction child; the docstring's "rejects bombs before any member is inflated" overstates this. *Fix:* enforce a per-entry and aggregate compression-ratio cap and/or inflate through a counting wrapper. (confirmed)

- **Redirect chain multiplies the fetch budget — 6 hops × fresh 60s timeout / 50 MB cap** — `proposal_assist/references/fetcher.py:218-285` — each redirect hop builds a new `httpx.Client(timeout=60)` and a fresh size accumulator, so a URL emitting 5 redirects to stalling public hosts holds one scarce `IngestLimiter` slot for ~360s; a handful exhaust the ingest subsystem on the single-instance host. *Fix:* compute a single cumulative deadline and byte budget once and pass the remaining budget into each hop. (confirmed)

- **Phase-3 citekey race wipes successfully-extracted metadata and marks the row failed** — `proposal_assist/references/ingest.py:249-302` — on a same-author/same-year collision the retry loop rolls back the in-session metadata assignments; after 4 collisions it re-raises into a fallback that opens a fresh session and unconditionally sets `metadata_status='failed'`, so a reference whose metadata *was* extracted ends up "failed" with `csl_json_extracted` never persisted — corrupting visible state purely from a citekey race. *Fix:* on final collision persist the metadata with a `ref-<hex>` citekey instead of failing; decouple "extraction failed" from "lost a citekey race." (confirmed)

- **Embed shrink-and-retry stores a vector that no longer represents the stored chunk text** — `embeddings/client.py:63-89` + `proposal_assist/references/ingest.py:144-160` — `embed()` halves over-long input down to 256 chars and returns the truncated-prefix vector, but ingest stores the *full* 1000-char `text` alongside it, so a dense chunk that trips bge-m3's long-input bug is embedded from ~25-50% of its text while the snippet shows all of it — silent RAG retrieval-quality degradation with `text_status='done'`. *Fix:* return the actually-embedded char count so ingest can store matching text, split-and-embed, or flag `embedding_truncated`. (confirmed)

### Pipeline / infra performance

## Low / Maintainability

### Auth & session (de-risked by internal threat model)

- **30-day session cookie with no idle timeout** — `auth/session_cookie.py:32` + `config.py:516` + `web/api/auth.py:111-118` — a stateless signed cookie stays valid for the full 30 days absent an epoch bump, giving a wide replay window for a leaked cookie (shared workstation, proxy log) on a security-sensitive tool. *Fix:* shorten the default (e.g. 7 days) and/or add an idle timeout via a last-activity field (the signer already round-trips a dict); at minimum document the 30-day window as deliberate risk acceptance. (medium-confidence)

- **CSRF middleware allows state-changing requests with no Origin and no Referer** — `auth/csrf.py:118-124` — falling through to allow matches Django's default and is fine for browsers (which always send Origin cross-site), but any non-browser internal client (curl, compromised internal service, SSRF pivot) bypasses the CSRF layer entirely, leaving defense to session cookie + SameSite=Lax. *Fix:* none required for the current threat model; if the surface broadens, require Origin on `/api` state-changing methods with a server-to-server allowlist, and document the decision. (Info-level; accepted-decision candidate)

- **Connect-Google link mode doesn't verify the linked email is allowlisted or matches the account** — `web/routes/oauth_google.py:134-143` + `auth/accounts.py:63-79` — link mode skips the `domain_allowed()` gate, so a user can bind a personal `gmail.com` identity to their institutional account; **not** an auth bypass today (non-link sign-in still hits the domain gate), but surprising and fragile if the gate is ever refactored. *Fix:* enforce `domain_allowed()` (or require email-equality) on the linked email, and pin the current "linked off-domain can't sign in" behavior with a test. (medium-confidence)

- **Password fields have no max length (argon2 CPU-amplification)** — `web/api/auth.py:35`, `web/api/me.py:131`, `auth/passwords.py:28` — `password`/`new_password` are bare `str`, so a multi-MB candidate drives proportional argon2 CPU; bounded by the 5/15min limiter and 64 MB body cap, and `/me/password` is reachable by any authenticated user. *Fix:* add `Field(max_length=1024)`, mirroring the existing `MAX_EMAIL_LEN` guard. (high-confidence)

- **`verify_password` never triggers an argon2 rehash on parameter upgrade** — `auth/passwords.py:28-36` — it never calls `check_needs_rehash` and returns only `bool`, so a future cost increase won't propagate to existing hashes. *Fix:* on successful verify, check `check_needs_rehash` and re-hash/persist in the login/change-password handlers. (maintainability)

- **Register leaks email-domain-allowlist membership via an argon2 timing oracle** — `web/api/auth.py:137-144` — a disallowed-domain register returns before the dummy argon2 op, so timing distinguishes allowed vs disallowed domains; **the allowlist is already public via `GET /auth/config`, so this leaks nothing secret** and the email-enumeration defense is sound. *Fix:* optional — add a comment noting the allowlist is intentionally public so future reviews don't re-flag this. # Improvement Opportunities — Feature & Usability

The product's read-models, backend hardening, and proposal-assist machinery are solid; the gaps cluster not in correctness but in **discovery, decision-support, and the operator/researcher feedback loops**. Four themes dominate:

- **Discovery is broken at the core.** The single highest-frequency action in a funding-discovery tool — free-text search — does not exist anywhere on the dashboard (it lives only as `must_include` feeding the email). Combined with no score filter, silent digest bucket caps, and silently-dropped failed-to-score calls, a researcher literally cannot reach calls 6–40 for their profile in a given week. This is the biggest value gap.
- **The "discover → decide → draft" journey has a hole in the middle.** Between "Hide" (permanent, no un-hide) and "Start drafting" (heavyweight, creates an artifact) there is no lightweight save/watch state and no way to get a deadline into a calendar. The decision step is binary and lossy — and it happens on phones (digest links) the desktop-only IDE shell doesn't support.
- **Silent failure is the dominant UX anti-pattern.** Across admin and researcher surfaces, rejected/no-op actions report success: golden-set adds swallow 409/400, collaborator-add fails on un-normalized email, "Send digest now" cheerfully reports success when the idempotency guard sent zero, failed/cancelled agent turns render a green ✓, and escalation cap-exhaustion leaves no breadcrumb. Each erodes trust in exactly the surfaces meant to build it.
- **Two systemic foundation gaps** — no responsive layout (zero `@media` anywhere) and no i18n (`lang="en"` for a Swedish hospital) — are cheap to scaffold now and expensive to retrofit later.

## High-value / near-term

- **Free-text search on the calls feed** — every researcher, every visit — Add `q` to `GET /api/calls` (ILIKE/pg_trgm over title+summary+full_text+keywords; the digest's escaped-ILIKE pattern in `assemble.py:178-209` is reusable) plus a debounced URL-bound input in `CallsFilters.tsx` following the existing `updateParam`/page-reset pattern. Single highest-ROI change in the product.
- **Score-band filter + "+N more" breadcrumbs** — researchers with many strong matches — Without a score filter and search, matches 6–40 are unreachable.
