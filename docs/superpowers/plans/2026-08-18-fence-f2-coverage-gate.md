# Fence F2 — Coverage Gate Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Status:** revision 3. Revision 1's detector unit was wrong; revision 2's verifier
tried to prove arbitrary Python is fenced and was wrong in four further ways. Revision
3 abandons that approach for a **canonical form**. See § Changelog.

**Goal:** Build the mechanical gate F3–F9 land against: an AST-derived inventory of
candidate effect sites with declared classification, locked against the tree, plus a
verifier that checks one canonical shape rather than attempting dataflow analysis.

**Architecture:** Detection is mechanical; classification is declared; verification is
**containment**, not analysis. A fenced site must put its whole effect inside a
canonical construct, and the gate checks that no bare effect sits outside one. That is
a bounded negative check over a tree — no dominance, no assignment resolution, no
ordering model.

**Tech Stack:** Python 3.12 stdlib `ast`, pytest. No database, no new dependency.

## The design decision, and why

Revisions 1 and 2 both tried to prove that arbitrary code is fenced. Each round the
verifier accepted a new class of invalid shape: a detached pre-check, a post-commit
mutex, a second unguarded write, a fence in a nested scope, a reassigned statement
variable, an ORM `session.add` with an unrelated guarded DML beside it. Every fix
added analysis and the next round found another hole, because proving arbitrary Python
is fenced is not decidable in a maintainable form.

This codebase already solved this exact class of problem. From
`proposal_assist/web/_writes.py`:

> *"This manager exists so the rule cannot be written wrongly. A route that uses it
> does not write a commit at all, so it cannot put the commit outside the bound."*

So F2 stops proving and starts **requiring**. Two canonical constructs, which **F3
introduces** — F2 only knows their names, the way a lint rule knows the name of the
thing it requires before that thing is common:

```python
# Mutex form — for git / filesystem / multi-row effects.
with fenced_write(session, workspace_id, generation=gen):
    session.add(ProposedChange(...))
    # the manager owns acquire_commit_mutex_at_generation AND the commit

# Predicate form — for a single DB-only statement, no lock, no lock-order risk.
fenced_execute(session, update(Job).values(x=1), workspace_id=ws, generation=gen)
# applies live_at_generation INSIDE the statement, so it is one statement by construction
```

**The whole verification rule then becomes:**

1. Every effect node (`.commit()`, a write `execute`, `.add()`) inside a fenced site
   is contained in a `with fenced_write(...)` block, **or** is a `fenced_execute(...)`
   call.
2. No bare effect node sits outside one.

Both primitives keep their place: `fenced_write` wraps Primitive B, `fenced_execute`
wraps Primitive A, so spec §5's lock-order rule is preserved — DB-only effects still
take no lock.

**What this dissolves rather than patches:** ordering (the manager owns it and cannot
be written wrongly), statement reassignment (irrelevant — `fenced_execute` applies the
predicate itself), ORM `session.add` (covered by containment), nested-scope
attribution (containment is per-node, not per-function). What it costs: F3 must
rewrite each fenced site into the canonical form. More work in F3, permanently less
machinery.

## Global Constraints

1. **F2 CONVERTS NO CALL SITES AND FENCES NOTHING.** Every inventory entry ends
   `fenced: false`. The only non-test change is the spec text in Task 6.
2. **F2 does NOT create `fenced_write` / `fenced_execute`.** F3 does. F2 knows their
   names only. Creating them here would break inertness and put unused production
   code on master.
3. **The inventory is NEVER regenerated by a test.** Regeneration is a script a human
   runs deliberately. A test that regenerates then compares to what it just generated
   always passes — a gate that cannot fail is worse than no gate.
4. **Site identity is `(kind, path, qualified_symbol)` — never a line number.**
   Qualified means `outer.inner` / `Class.method`.
5. **`.commit()` is NOT the same unit as "semantic effect."** Only sites classified
   `semantic` must fence. Spec §2 permits accounting on a stale generation and §7
   *requires* it — a gate that demanded a fence there would push F3 into stranding
   jobs and losing token accounting.
6. **Verification is containment, never analysis.** If a rule needs to know execution
   order, which branch ran, or what a name was last assigned, it is the wrong rule.
   Narrow the accepted syntax instead.
7. **Every verifier rule needs NEGATIVE fixtures.** A rule with only passing examples
   is a decorative test one level up.
8. `uv run ruff check .` is the gate — redirect to a log and read `$?`, never pipe
   into `tail`. Same for pytest. pytest exits **4** on "no tests ran": confirm a
   nonzero collected count.
9. Fast test runs: `uv run pytest -n 16 --dist loadfile`. Never `-n auto`, never
   `--dist loadgroup`.

Two pass `session_factory=None` and are excluded — they cannot originate a tool commit
so they carry no belief: `proposals/accepting.py` (request-driven, holds its own
session) and `tools/registry.py::collect_mcp_tool_names` (a static tool-name collector
using a zero UUID).

The remaining five are **not uniform**, and this is a blocking constraint on F3:

- **One-shot** — the background agents (`coherence`, `review`, `evaluator`,
  `uncited_claims`) build a ctx per run. The generation is known at construction, so
  it is **required at construction**.
- **Retained** — `drafting/factory.py::tools_factory` builds the interactive ctx
  during `controller.launch(...)`, and **launch deliberately happens BEFORE the claim**
  (`turns/processor.py:159` — the orphan sweep must run first so the subsequent claim
  does not trip the unique-running index). The claim generation does not exist yet.
  Requiring a value at construction would bless a placeholder or an unrelated live
  read — a stale belief wearing the fence's uniform.

  The correct stamp point is `set_turn_provenance`, already called **unconditionally
  every turn before `send_turn`** and already plumbed through
  contract → registry → adapter → ctx. `registry.py:80` documents why it is
  unconditional: the subprocess and its ctx are reused across turns, so a missed
  stamp leaks the previous turn's value.

So the inventory carries a `ctx_lifetime` field, and **F3's runtime two-turn test is
authoritative for the retained one** — no static check can see a per-turn re-stamp.

Expect the detector to report **9** `tool_commit`, **6** `claim_fn`, **5**
`tool_context`. These are hand counts to check the detector against, not gospel.

Create `tests/fencing/detectors.py`:

```python
"""Fence F2 — AST detectors for CANDIDATE effect sites.

Reads source as TEXT and imports nothing from `src/`. A gate that imports the
code it watches can be disarmed by the same refactor it exists to catch, and it
could not be unit-tested against synthetic fixtures.

These find CANDIDATES. Whether one is a semantic effect (must fence), accounting,
or covered by an enclosing critical section is DECLARED in fence_inventory.json:
`.commit()` is not the same unit as "semantic effect" (Global Constraint 5).

Site identity is (kind, path, qualified_symbol) — `outer.inner` / `Class.method`.
references.py has two committing helpers nested inside fetch_reference_impl, and
bare names would collapse same-named helpers across different outer functions.
"""

from __future__ import annotations

import ast
from typing import NamedTuple

KIND_TOOL_COMMIT = "tool_commit"
KIND_CLAIM_FN = "claim_fn"
KIND_TOOL_CONTEXT = "tool_context"

_TOOLS_DIR = "/proposal_assist/tools/"
_PROPOSAL_ASSIST = "/proposal_assist/"
_CLAIM_PREFIXES = ("claim_next_", "claim_queued_")

SCOPED = (ast.FunctionDef, ast.AsyncFunctionDef, ast.ClassDef)


class Site(NamedTuple):
    kind: str
    path: str
    symbol: str


def call_name(node: ast.Call) -> str | None:
    """The bare callee name of a Call: `f()` -> "f", `a.b.f()` -> "f"."""
    f = node.func
    return f.id if isinstance(f, ast.Name) else getattr(f, "attr", None)


def qualified_defs(tree: ast.AST) -> dict[str, ast.AST]:
    """Map dotted qualified name -> def/class node.

    The scope stack pushes ONLY on def/class over a full recursive walk, so a def
    nested inside a `with`/`if`/`try` still qualifies as `outer.helper`. Detector
    and verifier MUST resolve symbols identically or the gate reports phantom
    "symbol not found" for sites that exist.
    """
    found: dict[str, ast.AST] = {}

    def walk(node: ast.AST, stack: list[str]) -> None:
        for child in ast.iter_child_nodes(node):
            if isinstance(child, SCOPED):
                qual = stack + [child.name]
                found[".".join(qual)] = child
                walk(child, qual)
            else:
                walk(child, stack)

    walk(tree, [])
    return found


def find_sites(source: str, path: str) -> set[Site]:
    """Every candidate belief-carrying effect site in *source*. Pure."""
    norm = path.replace("\\", "/")
    tree = ast.parse(source)
    sites: set[Site] = set()

    def visit(node: ast.AST, stack: list[str]) -> None:
        if isinstance(node, SCOPED):
            if (
                isinstance(node, ast.FunctionDef | ast.AsyncFunctionDef)
                and _PROPOSAL_ASSIST in norm
                and node.name.startswith(_CLAIM_PREFIXES)
            ):
                sites.add(Site(KIND_CLAIM_FN, path, ".".join(stack + [node.name])))
            stack = stack + [node.name]

        elif isinstance(node, ast.Call):
            qual = ".".join(stack) if stack else "<module>"
            if (
                _TOOLS_DIR in norm
                and isinstance(node.func, ast.Attribute)
                and node.func.attr == "commit"
            ):
                sites.add(Site(KIND_TOOL_COMMIT, path, qual))

            if call_name(node) == "ToolContext":
                inert = any(
                    kw.arg == "session_factory"
                    and isinstance(kw.value, ast.Constant)
                    and kw.value.value is None
                    for kw in node.keywords
                )
                if not inert:
                    sites.add(Site(KIND_TOOL_CONTEXT, path, qual))

        for child in ast.iter_child_nodes(node):
            visit(child, stack)

    visit(tree, [])
    return sites
```

**Three defects this task exists to prevent:**

1. **Silent un-proving on rename.** Keying preservation on exact identity means a
   renamed fenced function loses its `true` flag and reappears as `false`. After F3
   deletes `test_f2_fences_nothing`, nothing catches it.
2. **Dropped declared fields.** A merge that rebuilds rows from a fixed key list
   silently discards `fenced_by` and `ctx_lifetime` — the very declarations the
   verifier depends on.
3. **Unvalidated rename maps.** A mapping whose old identity does not exist, or whose
   target is absent, is a typo. Silently ignoring it means the human believes a rename
   was carried across when it was not.

```python
"""Fence F2 — inventory load/merge, including the rename guard."""

from __future__ import annotations

import json
import pathlib

from tests.fencing.detectors import (
    KIND_CLAIM_FN,
    KIND_TOOL_COMMIT,
    KIND_TOOL_CONTEXT,
    Site,
    find_sites,
)

REPO = pathlib.Path(__file__).resolve().parents[2]
SRC = REPO / "src" / "call_manager"
INVENTORY = pathlib.Path(__file__).resolve().parent / "fence_inventory.json"

_SLICE_FOR_KIND = {KIND_CLAIM_FN: "F4"}
_DEFAULT_SLICE = "F3"

#: A site no human has classified yet. The gate REFUSES these, so a regeneration
#: cannot quietly admit an unreviewed effect site.
UNCLASSIFIED = "UNCLASSIFIED"

#: Which categories each kind may declare. Without this, a future tool_context
#: could be classified `accounting` and verify() would return success before its
#: kind-specific rule ever ran.
CATEGORIES_BY_KIND = {
    KIND_TOOL_COMMIT: frozenset({"semantic", "accounting", "caller_fenced", UNCLASSIFIED}),
    KIND_TOOL_CONTEXT: frozenset({"semantic", UNCLASSIFIED}),
    KIND_CLAIM_FN: frozenset({"semantic", UNCLASSIFIED}),
}
CATEGORIES = frozenset().union(*CATEGORIES_BY_KIND.values())

#: Extra declared keys, preserved verbatim across regeneration — they are what
#: the verifier reads.
OPTIONAL_KEYS = ("fenced_by", "ctx_lifetime")


class FencedSiteVanished(RuntimeError):
    """A previously FENCED identity is missing from the new scan.

    Almost always a rename. Left to a naive merge it would drop a `true` entry
    and add a `false` one, silently un-proving a site — and after F3 deletes
    `test_f2_fences_nothing`, nothing else would catch it.
    """

    def __init__(self, lost: list[tuple[str, str, str]]) -> None:
        super().__init__(
            "previously fenced sites are gone from the scan:\n  "
            + "\n  ".join(f"{k} {p}::{s}" for k, p, s in lost)
            + "\n\nIf RENAMED, add a RENAMES mapping. If genuinely deleted, remove "
            "the entries by hand and say so in the commit message."
        )
        self.lost = lost


class BadRenameMap(RuntimeError):
    """A rename mapping that cannot apply: an unknown old identity, or a target
    absent from the scan. Both are typos. Ignoring either would let a human
    believe a rename carried a proof across when it did not."""


def scan_tree() -> set[Site]:
    sites: set[Site] = set()
    for p in sorted(SRC.rglob("*.py")):
        if "__pycache__" in p.parts:
            continue
        sites |= find_sites(p.read_text(encoding="utf-8"), p.relative_to(REPO).as_posix())
    return sites


def load_inventory() -> list[dict]:
    return json.loads(INVENTORY.read_text(encoding="utf-8"))


def merge(
    previous: list[dict],
    found: set[Site],
    renames: dict[tuple[str, str, str], tuple[str, str, str]] | None,
) -> list[dict]:
    """Fold *found* into *previous*, preserving `fenced`, `category` and every
    declared optional key.

    Validates the WHOLE rename map up front, then aborts if any previously-fenced
    identity is still missing.
    """
    renames = renames or {}
    prev_by_id = {(r["kind"], r["path"], r["symbol"]): r for r in previous}
    found_ids = {(s.kind, s.path, s.symbol) for s in found}

    bad = []
    for old, new in renames.items():
        if old not in prev_by_id:
            bad.append(f"old identity not in the inventory: {old}")
        if new not in found_ids:
            bad.append(f"target not found in the scan: {new}")
    if bad:
        raise BadRenameMap("unusable rename mapping(s):\n  " + "\n  ".join(bad))

    for old, new in renames.items():
        row = prev_by_id.pop(old)
        prev_by_id[new] = {**row, "kind": new[0], "path": new[1], "symbol": new[2]}

    lost = sorted(i for i, r in prev_by_id.items() if r["fenced"] and i not in found_ids)
    if lost:
        raise FencedSiteVanished(lost)

    rows = []
    for s in sorted(found):
        prev = prev_by_id.get((s.kind, s.path, s.symbol))
        row = {
            "kind": s.kind,
            "path": s.path,
            "symbol": s.symbol,
            "category": prev["category"] if prev else UNCLASSIFIED,
            "fenced": prev["fenced"] if prev else False,
            "slice": _SLICE_FOR_KIND.get(s.kind, _DEFAULT_SLICE),
        }
        if prev:
            for key in OPTIONAL_KEYS:
                if key in prev:
                    row[key] = prev[key]
        rows.append(row)
    return rows
```

**Interfaces:**
- Produces: `verify(row: dict, source: str) -> list[str]` — reasons the site is not
  properly fenced; empty list means it is. Takes the whole row so it can read
  `category`, `fenced_by` and `ctx_lifetime`.

**The rules. Every one is containment, never analysis (Global Constraint 6).**

An **effect node** is: a `.commit()` call, a `.add()` call, or an `.execute(...)` call
whose first argument anywhere contains `update(`/`insert(`/`delete(`.

A **fenced region** is the body of a `with fenced_write(...)` statement. A
`fenced_execute(...)` call is itself fenced.

- `tool_commit` + `semantic`: every effect node in the function's **own scope**
  (excluding nested defs, which are their own sites) must be inside a fenced region or
  be a `fenced_execute` call. At least one effect must exist.
- `tool_commit` + `accounting`: **no fence required.** Spec §2 permits these on a
  stale generation and §7 requires them to still run.
- `tool_commit` + `caller_fenced`: the ancestor named by `fenced_by` must resolve in
  the same file and must contain a call to this site's own name **inside its fenced
  region**. Containment again — no dominance analysis.
- `tool_context` + `one_shot`: the `ToolContext(...)` call must pass
  `lifecycle_generation=` with a non-`None` value.
- `tool_context` + `retained`: **no construction-time value required** — see the
  research note. F3's runtime two-turn test is authoritative.
- `claim_fn`: must **write** `claimed_at_generation` — an assignment target attribute,
  or a `claimed_at_generation=` keyword — in its own scope. A read, a bare string, or
  a write in a nested def does not count. **Stated boundary:** atomicity comes from the
  existing `FOR UPDATE` inside one transaction, not from statement form, so this is a
  write-presence check and the docstring says so.

Create `tests/fencing/verifiers.py`:

```python
"""Fence F2 — canonical-form verification.

Verification is CONTAINMENT, not analysis (Global Constraint 6). Revisions 1 and
2 tried to prove arbitrary code was fenced and each accepted a new class of
invalid shape — a detached pre-check, a post-commit mutex, a second unguarded
write, a fence in a nested scope, a reassigned statement variable, a bare ORM
add. Proving arbitrary Python is fenced is not decidable in a maintainable form.

So a fenced site must be WRITTEN in the canonical form instead:

    with fenced_write(session, ws, generation=gen):   # mutex form
        ...
    fenced_execute(session, stmt, workspace_id=ws, generation=gen)   # predicate form

and the rule is: every effect node is inside one, and none sits outside. Same
principle as proposal_assist/web/_writes.py — "exists so the rule cannot be
written wrongly".

F3 creates the two constructs. This module knows their names only.
"""

from __future__ import annotations

import ast

from tests.fencing.detectors import (
    KIND_CLAIM_FN,
    KIND_TOOL_COMMIT,
    KIND_TOOL_CONTEXT,
    SCOPED,
    call_name,
    qualified_defs,
)

FENCED_WRITE = "fenced_write"
FENCED_EXECUTE = "fenced_execute"
GENERATION_KW = "lifecycle_generation"
CLAIM_COLUMN = "claimed_at_generation"

#: Produces no semantic result. Spec 2 permits these on a stale generation and
#: spec 7 REQUIRES them to still run — demanding a fence would push F3 into
#: stranding jobs and losing token accounting.
NO_FENCE_REQUIRED = frozenset({"accounting"})

_WRITE_CTORS = frozenset({"update", "insert", "delete"})


def _own_nodes(scope: ast.AST):
    """Every node in *scope*, NOT descending into nested defs/classes.

    A nested def is its own site with its own inventory entry, so a fence inside
    one does not cover its parent and vice versa.
    """
    for child in ast.iter_child_nodes(scope):
        if isinstance(child, SCOPED):
            continue
        yield child
        yield from _own_nodes(child)


def _is_effect(node: ast.AST) -> bool:
    if not isinstance(node, ast.Call):
        return False
    name = call_name(node)
    if name in {"commit", "add"}:
        return True
    if name == "execute" and node.args:
        return any(
            isinstance(n, ast.Call) and call_name(n) in _WRITE_CTORS
            for n in ast.walk(node.args[0])
        )
    return False


def _fenced_regions(scope: ast.AST) -> list[ast.AST]:
    """`with fenced_write(...)` statements in *scope*'s own code."""
    out = []
    for node in _own_nodes(scope):
        if isinstance(node, ast.With | ast.AsyncWith) and any(
            isinstance(item.context_expr, ast.Call)
            and call_name(item.context_expr) == FENCED_WRITE
            for item in node.items
        ):
            out.append(node)
    return out


def _covered_ids(scope: ast.AST) -> set[int]:
    """id()s of every node inside a fenced region, plus fenced_execute calls."""
    covered: set[int] = set()
    for region in _fenced_regions(scope):
        for n in ast.walk(region):
            covered.add(id(n))
    for node in _own_nodes(scope):
        if isinstance(node, ast.Call) and call_name(node) == FENCED_EXECUTE:
            covered.add(id(node))
    return covered


def _verify_semantic_commit(scope: ast.AST) -> list[str]:
    covered = _covered_ids(scope)
    effects = [n for n in _own_nodes(scope) if _is_effect(n)]
    fenced_execs = [
        n for n in _own_nodes(scope)
        if isinstance(n, ast.Call) and call_name(n) == FENCED_EXECUTE
    ]
    if not effects and not fenced_execs:
        return [
            "no effect found — a semantic site that writes nothing is a "
            "misclassification, not a pass"
        ]
    bare = [n for n in effects if id(n) not in covered]
    if bare:
        names = sorted({call_name(n) or "?" for n in bare})
        return [
            f"{len(bare)} effect(s) outside the canonical form: {names}. Put them "
            f"inside `with {FENCED_WRITE}(...)` or use `{FENCED_EXECUTE}(...)`"
        ]
    return []


def _verify_caller_fenced(row: dict, defs: dict[str, ast.AST]) -> list[str]:
    ancestor_name = row.get("fenced_by")
    if not ancestor_name:
        return ["caller_fenced but no `fenced_by` declared"]
    ancestor = defs.get(ancestor_name)
    if ancestor is None:
        return [f"`fenced_by` {ancestor_name!r} does not resolve in this file"]
    own_name = row["symbol"].rsplit(".", 1)[-1]
    for region in _fenced_regions(ancestor):
        for n in ast.walk(region):
            if isinstance(n, ast.Call) and call_name(n) == own_name:
                return []
    return [
        f"{ancestor_name} does not call {own_name} inside a "
        f"`with {FENCED_WRITE}(...)` region"
    ]


def _verify_tool_context(row: dict, scope: ast.AST) -> list[str]:
    lifetime = row.get("ctx_lifetime")
    if lifetime == "retained":
        # Built during launch, which deliberately precedes the claim
        # (turns/processor.py:159) — the generation does not exist yet.
        # Requiring one here would bless a placeholder. F3's runtime two-turn
        # test is authoritative for this site.
        return []
    if lifetime != "one_shot":
        return [f"ctx_lifetime must be one_shot or retained, got {lifetime!r}"]
    for node in _own_nodes(scope):
        if isinstance(node, ast.Call) and call_name(node) == "ToolContext":
            kw = next((k for k in node.keywords if k.arg == GENERATION_KW), None)
            if kw is None:
                return [f"ToolContext(...) does not pass {GENERATION_KW}="]
            if isinstance(kw.value, ast.Constant) and kw.value.value is None:
                return [f"ToolContext(...) passes {GENERATION_KW}=None"]
            return []
    return ["no ToolContext(...) construction found"]


def _verify_claim_fn(scope: ast.AST) -> list[str]:
    """WRITE-presence, in this scope only.

    A read, a bare string, or a write inside a nested def does not count.

    Stated boundary: atomicity at claim time comes from the existing `FOR UPDATE`
    row lock inside one transaction, not from statement form — the ORM idiom sets
    the column in its own statement and is still atomic. Claiming to verify
    atomicity statically would be an over-claim.
    """
    for node in _own_nodes(scope):
        if isinstance(node, ast.Assign):
            for t in node.targets:
                if isinstance(t, ast.Attribute) and t.attr == CLAIM_COLUMN:
                    return []
        if isinstance(node, ast.keyword) and node.arg == CLAIM_COLUMN:
            return []
    return [f"the claim does not WRITE {CLAIM_COLUMN} in its own scope"]


def verify(row: dict, source: str) -> list[str]:
    """Reasons this site is not properly fenced. Empty list = it is."""
    kind, category = row["kind"], row["category"]
    if kind == KIND_TOOL_COMMIT and category in NO_FENCE_REQUIRED:
        return []

    tree = ast.parse(source)
    defs = qualified_defs(tree)
    scope = tree if row["symbol"] == "<module>" else defs.get(row["symbol"])
    if scope is None:
        return [f"symbol {row['symbol']!r} not found"]

    if kind == KIND_TOOL_COMMIT:
        if category == "caller_fenced":
            return _verify_caller_fenced(row, defs)
        return _verify_semantic_commit(scope)
    if kind == KIND_TOOL_CONTEXT:
        return _verify_tool_context(row, scope)
    if kind == KIND_CLAIM_FN:
        return _verify_claim_fn(scope)
    return [f"unknown kind {kind!r}"]
```

- **Nothing is fenced**, and `fenced_write`/`fenced_execute` do not exist. F3 creates
  them, rewrites the six semantic sites into the canonical form, flips those entries,
  and deletes `test_f2_fences_nothing` in the same commit.

- **The retained context's per-turn re-stamp is NOT covered, and this is the important

  interactive ctx cannot carry a generation at construction — launch precedes the
  claim by design — so its correctness rests entirely on an unconditional stamp at
  `set_turn_provenance`. That is runtime, and it is the highest-risk silent failure in
  the architecture: `registry.py:80` documents the identical trap for provenance,
  where a stamp missed once leaks the previous turn's value. **F3 must prove it with a
  runtime test**: drive two turns through one retained ctx across a generation change
  and assert the second carries the new one.
- **`claim_fn` verification is write-presence, not atomicity.** Atomicity comes from
  the existing `FOR UPDATE` inside one transaction. Stated rather than over-claimed.
- **`caller_fenced` is verified within one file.** The ancestor must resolve in the

**Revision 3** — after the second review. Changes:

- **Verification is now containment, not analysis.** Revisions 1 and 2 tried to prove
  arbitrary code fenced; each accepted a new class of invalid shape. Revision 3
  requires the canonical `fenced_write` / `fenced_execute` form and checks that no
  effect sits outside it. This dissolves rather than patches: mutex ordering (the
  manager owns it), statement reassignment (moot), bare ORM `session.add` (covered by
  containment), nested-scope attribution (per-node). Task 4 Step 7 restores revision
  2's check and requires four named tests to go red.
- **`caller_fenced` is verified, not just named.** The ancestor must resolve AND
  contain a call to the site inside its fenced region. Four negative fixtures.
- **`tool_context` splits by lifetime.** The retained interactive ctx is built during
  launch, which deliberately precedes the claim (`turns/processor.py:159`), so it
  cannot carry a generation at construction — requiring one would bless a placeholder.
  One-shot contexts still must.
- **`claim_fn` requires a WRITE in its own scope.** Revision 2's unrestricted
  `ast.walk` accepted a read, a nested-scope write, or a bare string.
- **Categories are enforced per kind.** Otherwise a future `tool_context` classified
  `accounting` would short-circuit to success before its rule ran.
- **`admission` folded into `accounting`.** Revision 2 invented a fourth category the
  spec does not define; Task 6 widens spec §2's wording instead.
- **Merge preserves declared optional fields** (`fenced_by`, `ctx_lifetime`) and
  **validates the whole rename map up front** — an unknown old identity or an absent
  target is a typo, not permission.
- **Added Task 6 steps** for spec §2, §3 and §9 alongside §4.1.
