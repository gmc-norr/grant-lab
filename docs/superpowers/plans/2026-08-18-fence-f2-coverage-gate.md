# Fence F2 — Coverage Gate Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Status:** revision 2. Revision 1 was reviewed and found to have three blocking gate
defects — the detector's unit was wrong, the verifier accepted the exact decorative
shapes it exists to reject, and regeneration silently un-proved renamed sites. See
§ Changelog.

**Goal:** Build the mechanical gate F3–F9 land against: an AST-derived inventory of
candidate effect sites with a declared category, locked against the tree, plus
kind-and-shape-aware verifiers that a site marked fenced really is fenced.

**Architecture:** Detection is mechanical, classification is declared. Detectors find
*candidate* sites and return `(kind, path, qualified_symbol)`. A checked-in JSON
inventory adds a human-declared `category` per site — only `semantic` sites must
fence. Verifiers are per-kind and shape-aware, proven against negative fixtures.

**Tech Stack:** Python 3.12 stdlib `ast`, pytest. No database, no new dependency.

## Global Constraints

1. **F2 CONVERTS NO CALL SITES AND FENCES NOTHING.** Every inventory entry ends
   `fenced: false`. F2 builds the instrument, not the fix. No `src/` change except
   the spec-text update in Task 6.
2. **The inventory is NEVER regenerated by a test.** Regeneration is a script a human
   runs deliberately. A test that regenerates and then compares to what it just
   generated always passes — a gate that cannot fail is worse than no gate, because
   every later slice would trust it.
3. **Site identity is `(kind, path, qualified_symbol)` — never a line number.**
   Qualified means `outer.inner` / `Class.method`. A bare name collapses two nested
   functions that share a name into one entry, and `references.py` already has two
   nested helpers inside `fetch_reference_impl`.
4. **`.commit()` is NOT the same unit as "semantic effect".** The spec's §2 table
   distinguishes semantic effects (fenced), cleanup/accounting (permitted on a stale
   generation, via CAS), and delivered reads. A gate that demands a fence inside every
   committing function would reject correct caller-held fencing and would actively
   encourage fencing cleanup — which spec §7 forbids, because a stale actor that
   writes nothing strands its job and loses token accounting.
5. **Detector and verifier logic is tested against synthetic fixtures, not the live
   tree.** Asserting against real files only proves the code agrees with itself today.
6. **Every verifier needs NEGATIVE fixtures.** A verifier that only has passing
   examples is the decorative test one level up.
7. `uv run ruff check .` is the gate — redirect to a log and read `$?`, never pipe
   into `tail`. Same for every pytest run.
8. Fast test runs: `uv run pytest -n 16 --dist loadfile`. Never `-n auto`, never
   `--dist loadgroup`. pytest exits **4** on "no tests ran" — confirm a nonzero
   collected count.

Create `tests/fencing/detectors.py`:

```python
"""Fence F2 — AST detectors for CANDIDATE effect sites.

Reads source as TEXT and imports nothing from `src/`. A gate that imports the
code it watches can be disarmed by the same refactor it exists to catch, and it
could not be unit-tested against synthetic fixtures.

These find CANDIDATES. Whether a candidate is a semantic effect (must fence),
admission, cleanup, or covered by an enclosing critical section is a judgment
DECLARED in fence_inventory.json — `.commit()` is not the same unit as "semantic
effect" (Global Constraint 4).

Site identity is (kind, path, qualified_symbol). Qualified means `outer.inner` /
`Class.method`: references.py has two committing helpers nested inside
fetch_reference_impl, and bare names would collapse same-named nested helpers
across different outer functions.
"""

from __future__ import annotations

import ast
from typing import NamedTuple

KIND_TOOL_COMMIT = "tool_commit"
KIND_CLAIM_FN = "claim_fn"
KIND_TOOL_CONTEXT = "tool_context"

_TOOLS_DIR = "/proposal_assist/tools/"
_PROPOSAL_ASSIST = "/proposal_assist/"
_CLAIM_PREFIXES = ("claim_next_", "claim_queued_")

_SCOPED = (ast.FunctionDef, ast.AsyncFunctionDef, ast.ClassDef)


class Site(NamedTuple):
    kind: str
    path: str
    symbol: str


def _qual(stack: list[str]) -> str:
    return ".".join(stack) if stack else "<module>"


def find_sites(source: str, path: str) -> set[Site]:
    """Every candidate belief-carrying effect site in *source*.

    Pure: same inputs, same output, no filesystem access.
    """
    norm = path.replace("\\", "/")
    tree = ast.parse(source)
    sites: set[Site] = set()

    def visit(node: ast.AST, stack: list[str]) -> None:
        if isinstance(node, _SCOPED):
            if (
                isinstance(node, ast.FunctionDef | ast.AsyncFunctionDef)
                and _PROPOSAL_ASSIST in norm
                and node.name.startswith(_CLAIM_PREFIXES)
            ):
                sites.add(Site(KIND_CLAIM_FN, path, _qual(stack + [node.name])))
            stack = stack + [node.name]

        elif isinstance(node, ast.Call):
            func = node.func
            if (
                _TOOLS_DIR in norm
                and isinstance(func, ast.Attribute)
                and func.attr == "commit"
            ):
                sites.add(Site(KIND_TOOL_COMMIT, path, _qual(stack)))

            name = func.id if isinstance(func, ast.Name) else getattr(func, "attr", None)
            if name == "ToolContext":
                inert = any(
                    kw.arg == "session_factory"
                    and isinstance(kw.value, ast.Constant)
                    and kw.value.value is None
                    for kw in node.keywords
                )
                if not inert:
                    sites.add(Site(KIND_TOOL_CONTEXT, path, _qual(stack)))

        for child in ast.iter_child_nodes(node):
            visit(child, stack)

    visit(tree, [])
    return sites
```

**The defect this task exists to prevent.** Keying preservation on exact identity
means: rename a fenced function, regenerate, and the `true` entry silently
disappears while a new `false` one takes its place. After F3 deletes
`test_f2_fences_nothing`, nothing catches it and CI stays green on an unfenced
site that was previously proven. So the merge must **abort** when a previously
fenced identity vanishes, and require either an explicit rename mapping or a
deliberate override.

```python
"""Fence F2 — inventory load/merge, including the rename guard."""

from __future__ import annotations

import json
import pathlib

from tests.fencing.detectors import KIND_CLAIM_FN, Site, find_sites

REPO = pathlib.Path(__file__).resolve().parents[2]
SRC = REPO / "src" / "call_manager"
INVENTORY = pathlib.Path(__file__).resolve().parent / "fence_inventory.json"

_SLICE_FOR_KIND = {KIND_CLAIM_FN: "F4"}
_DEFAULT_SLICE = "F3"

#: A site that has not been classified by a human yet. The gate refuses these,
#: so a regeneration cannot quietly admit an unreviewed effect site.
UNCLASSIFIED = "UNCLASSIFIED"

#: Declared categories. Only `semantic` must fence.
CATEGORIES = frozenset(
    {"semantic", "admission", "cleanup", "caller_fenced", UNCLASSIFIED}
)


class FencedSiteVanished(RuntimeError):
    """A previously FENCED identity is not in the new scan.

    Almost always a rename. Left to the default merge it would drop a `true`
    entry and add a `false` one, silently un-proving a site — and after F3
    deletes `test_f2_fences_nothing`, nothing else would catch it.
    """

    def __init__(self, lost: list[tuple[str, str, str]]) -> None:
        super().__init__(
            "previously fenced sites are gone from the scan:\n  "
            + "\n  ".join(f"{k} {p}::{s}" for k, p, s in lost)
            + "\n\nIf these were RENAMED, pass a rename mapping. If they were "
            "genuinely deleted, remove the entries by hand and say so in the "
            "commit message. Do not regenerate over them."
        )
        self.lost = lost


def scan_tree() -> set[Site]:
    sites: set[Site] = set()
    for p in sorted(SRC.rglob("*.py")):
        if "__pycache__" in p.parts:
            continue
        sites |= find_sites(p.read_text(encoding="utf-8"), p.relative_to(REPO).as_posix())
    return sites


def load_inventory() -> list[dict]:
    return json.loads(INVENTORY.read_text(encoding="utf-8"))


def merge(
    previous: list[dict],
    found: set[Site],
    renames: dict[tuple[str, str, str], tuple[str, str, str]] | None,
) -> list[dict]:
    """Fold *found* into *previous*, preserving `fenced` and `category`.

    Raises FencedSiteVanished if any previously-fenced identity is absent from
    *found* and is not carried across by *renames* to an identity that IS
    present. A rename mapping whose target is absent is a typo, not permission.
    """
    renames = renames or {}
    prev_by_id = {(r["kind"], r["path"], r["symbol"]): r for r in previous}
    found_ids = {(s.kind, s.path, s.symbol) for s in found}

    # Apply renames first, so the guard below sees the carried-across identity.
    for old, new in renames.items():
        row = prev_by_id.pop(old, None)
        if row is not None and new in found_ids:
            prev_by_id[new] = {**row, "kind": new[0], "path": new[1], "symbol": new[2]}

    lost = sorted(i for i, r in prev_by_id.items() if r["fenced"] and i not in found_ids)
    if lost:
        raise FencedSiteVanished(lost)

    rows = []
    for s in sorted(found):
        prev = prev_by_id.get((s.kind, s.path, s.symbol))
        rows.append(
            {
                "kind": s.kind,
                "path": s.path,
                "symbol": s.symbol,
                "category": prev["category"] if prev else UNCLASSIFIED,
                "fenced": prev["fenced"] if prev else False,
                "slice": _SLICE_FOR_KIND.get(s.kind, _DEFAULT_SLICE),
            }
        )
    return rows
```

### Task 4: Kind-specific, shape-aware verifiers

**Files:**
- Create: `tests/fencing/verifiers.py`
- Test: `tests/fencing/test_verifiers.py`
- Modify: `tests/fencing/test_fence_coverage.py` (append one test)

**Interfaces:**
- Produces: `verify(kind: str, category: str, source: str, symbol: str) -> list[str]`
  — returns a list of human-readable reasons the site is NOT properly fenced. Empty
  list means it is.

**Why the naive version is wrong.** A verifier that returns true on finding a
primitive call *anywhere* in the function accepts every shape this architecture
forbids:

1. `live_at_generation(...)` as a **detached pre-check** rather than inside the write
   statement — the two-statement defect that shipped twice (`28abbc4`, `701fbb7`).
2. Primitive B called **after** the semantic commit.
3. One guarded write and a second **unguarded** write in the same function.
4. A fence inside a **nested** function while the outer function's own effect is bare.

It also cannot honestly verify two of the three kinds: `tool_context` must prove the
generation is *propagated*, not that a fence is called; `claim_fn` must prove the
column is *recorded*.

**Rules to implement, per kind:**

- `tool_commit`, category `semantic`, using **Primitive A**: every
  `session.execute(<expr>)` whose `<expr>` builds a write (`update(`/`insert(`/
  `delete(`) must have `live_at_generation(...)` as a descendant of that same
  expression. Resolve one level of indirection: if the argument is a `Name`, follow
  its most recent assignment in the function.
- `tool_commit`, category `semantic`, using **Primitive B**: an
  `acquire_commit_mutex_at_generation(...)` call must appear at a statement index
  strictly **before** every `.commit()` in the function body.
- `tool_commit`, category `admission` / `cleanup`: **no fence required.** Spec §2
  permits these on a stale generation and §7 requires cleanup to still run.
- `tool_commit`, category `caller_fenced`: the entry must name its fencing ancestor
  in a `fenced_by` field, and that ancestor must itself verify.
- `tool_context`: the `ToolContext(...)` call must pass a `lifecycle_generation=`
  keyword whose value is not `None`.
- `claim_fn`: the function must reference `claimed_at_generation`. **Stated
  boundary:** atomicity comes from the existing `FOR UPDATE` + single transaction,
  not from single-statement form, so this check is presence only — do not pretend
  otherwise in the docstring.
- Nested functions are never searched when verifying their parent.

```python
`verify` returns REASONS a site is not properly fenced; an empty list means it
is. Reasons rather than a bool so the gate can tell a human what is wrong.

The shapes rejected here are the ones a naive "is a primitive called anywhere in
this function" check accepts, and every one of them is a real defect class:

  * a DETACHED pre-check instead of a predicate inside the write statement — the
    two-statement defect that shipped twice (28abbc4, 701fbb7);
  * Primitive B called AFTER the commit it is meant to guard;
  * one guarded write beside a second unguarded one;
  * a fence in a NESTED function while the parent's own effect is bare.
"""

from __future__ import annotations

import ast

from tests.fencing.detectors import KIND_CLAIM_FN, KIND_TOOL_COMMIT, KIND_TOOL_CONTEXT

PREDICATE = "live_at_generation"
MUTEX = "acquire_commit_mutex_at_generation"
GENERATION_KW = "lifecycle_generation"
CLAIM_COLUMN = "claimed_at_generation"

#: Categories that produce no semantic result. Spec 2 permits them on a stale
#: generation and spec 7 REQUIRES cleanup to still run — demanding a fence here
#: would push F3 into stranding jobs and losing token accounting.
NO_FENCE_REQUIRED = frozenset({"admission", "cleanup"})

_WRITE_CTORS = frozenset({"update", "insert", "delete"})
_SCOPED = (ast.FunctionDef, ast.AsyncFunctionDef, ast.ClassDef)


def _find(tree: ast.AST, symbol: str) -> ast.AST | None:
    """The def named by a dotted *symbol*, or the module for "<module>".

    Builds the qualified-name map the SAME way detectors.py does — a scope stack
    pushed only on def/class, over a full recursive walk. Anything narrower
    breaks on a def nested inside a `with`, `if` or `try`, which is not a direct
    child of the enclosing function body: the detector would emit `outer.helper`
    and the verifier would fail to resolve it, silently reporting "symbol not
    found" for a site that exists. Detector and verifier MUST agree on symbol
    resolution or the gate reports phantom failures.
    """
    if symbol == "<module>":
        return tree

    found: dict[str, ast.AST] = {}

    def walk(node: ast.AST, stack: list[str]) -> None:
        for child in ast.iter_child_nodes(node):
            if isinstance(child, _SCOPED):
                qual = stack + [child.name]
                found[".".join(qual)] = child
                walk(child, qual)
            else:
                walk(child, stack)

    walk(tree, [])
    return found.get(symbol)


def _own_nodes(fn: ast.AST):
    """Every node in *fn*, NOT descending into nested defs.

    Attribution matters: a fence inside a nested helper does not fence its
    parent, and references.py really nests committing helpers.
    """
    for child in ast.iter_child_nodes(fn):
        if isinstance(child, _SCOPED):
            continue
        yield child
        yield from _own_nodes(child)


def _calls_named(node: ast.AST, name: str) -> bool:
    for n in ast.walk(node):
        if isinstance(n, ast.Call):
            f = n.func
            if (f.id if isinstance(f, ast.Name) else getattr(f, "attr", None)) == name:
                return True
    return False


def _is_write_stmt(expr: ast.AST) -> bool:
    return any(
        isinstance(n, ast.Call)
        and (n.func.id if isinstance(n.func, ast.Name) else getattr(n.func, "attr", None))
        in _WRITE_CTORS
        for n in ast.walk(expr)
    )


def _verify_tool_commit(fn: ast.AST) -> list[str]:
    own = list(_own_nodes(fn))

    # Primitive B: the mutex must precede EVERY commit, in body order.
    body = getattr(fn, "body", [])
    mutex_at = next(
        (i for i, st in enumerate(body) if _calls_named(st, MUTEX)), None
    )
    if mutex_at is not None:
        commits_at = [
            i
            for i, st in enumerate(body)
            if any(
                isinstance(n, ast.Call)
                and isinstance(n.func, ast.Attribute)
                and n.func.attr == "commit"
                for n in ast.walk(st)
            )
        ]
        late = [i for i in commits_at if i <= mutex_at]
        if late:
            return [
                f"{MUTEX} is called at statement {mutex_at} but a commit happens "
                f"at or before it (statements {late}) — fencing after the effect "
                f"has landed fences nothing"
            ]
        return []

    # Primitive A: every write-execute must carry the predicate INSIDE it.
    assigned: dict[str, ast.AST] = {}
    for node in own:
        if isinstance(node, ast.Assign) and len(node.targets) == 1:
            t = node.targets[0]
            if isinstance(t, ast.Name):
                assigned[t.id] = node.value

    writes, guarded = 0, 0
    for node in own:
        if not (
            isinstance(node, ast.Call)
            and isinstance(node.func, ast.Attribute)
            and node.func.attr == "execute"
            and node.args
        ):
            continue
        arg = node.args[0]
        # One level of indirection: `stmt = update(...)` then `execute(stmt)`.
        target = assigned.get(arg.id, arg) if isinstance(arg, ast.Name) else arg
        if not _is_write_stmt(target):
            continue
        writes += 1
        if _calls_named(target, PREDICATE):
            guarded += 1

    if writes == 0:
        return [
            "no fence found: the function calls neither "
            f"{MUTEX} nor a write statement carrying {PREDICATE}"
        ]
    if guarded < writes:
        return [
            f"{writes - guarded} of {writes} write statement(s) do not carry "
            f"{PREDICATE} inside the executed statement — a detached pre-check "
            f"does not guard a later write (28abbc4, 701fbb7)"
        ]
    return []


def _verify_tool_context(fn: ast.AST) -> list[str]:
    for node in _own_nodes(fn):
        if not isinstance(node, ast.Call):
            continue
        f = node.func
        if (f.id if isinstance(f, ast.Name) else getattr(f, "attr", None)) != "ToolContext":
            continue
        kw = next((k for k in node.keywords if k.arg == GENERATION_KW), None)
        if kw is None:
            return [f"ToolContext(...) does not pass {GENERATION_KW}="]
        if isinstance(kw.value, ast.Constant) and kw.value.value is None:
            return [f"ToolContext(...) passes {GENERATION_KW}=None"]
        return []
    return ["no ToolContext(...) construction found"]


def _verify_claim_fn(fn: ast.AST) -> list[str]:
    """Presence only, and deliberately so.

    Atomicity at claim time comes from the existing `FOR UPDATE` row lock inside
    one transaction, not from single-statement form — the ORM idiom sets the
    column in its own statement and is still atomic. Claiming to verify
    atomicity statically here would be an over-claim.
    """
    for node in ast.walk(fn):
        if isinstance(node, ast.Attribute) and node.attr == CLAIM_COLUMN:
            return []
        if isinstance(node, ast.keyword) and node.arg == CLAIM_COLUMN:
            return []
        if isinstance(node, ast.Constant) and node.value == CLAIM_COLUMN:
            return []
    return [f"the claim does not record {CLAIM_COLUMN}"]


def verify(kind: str, category: str, source: str, symbol: str) -> list[str]:
    """Reasons *symbol* is not properly fenced. Empty list = it is."""
    if category in NO_FENCE_REQUIRED:
        return []

    fn = _find(ast.parse(source), symbol)
    if fn is None:
        return [f"symbol {symbol!r} not found"]

    if kind == KIND_TOOL_COMMIT:
        return _verify_tool_commit(fn)
    if kind == KIND_TOOL_CONTEXT:
        return _verify_tool_context(fn)
    if kind == KIND_CLAIM_FN:
        return _verify_claim_fn(fn)
    return [f"unknown kind {kind!r}"]
```

## What F2 deliberately leaves undone

- **Nothing is fenced.** F3 flips the first entries and deletes
  `test_f2_fences_nothing` in the same commit.
- **Three kinds, not every effect in the spec.** Room writes, turn finalizers and
  pass-runner milestones are not detectable by rules this simple — "is this commit
  reached from a claim?" is not syntactically decidable. F5–F7 add kinds of their
  own, against fixtures, the same way. A gate that silently implied full coverage
  would be worse than one with a stated boundary.
- **The per-turn re-stamp is NOT covered, and this is the important gap.** Spec §9
  wants the gate to assert every `ToolContext` construction "stamps the generation
  per turn". F2 verifies a construction *passes* a generation; it cannot see whether
  it is re-stamped on every `send_turn`. That is runtime, and it is the highest-risk
  silent failure in the architecture — `registry.py:80` documents the identical trap
  for provenance, where a stamp missed once leaks the previous turn's value. **F3
  must prove it with a runtime test**: drive two turns through one retained ctx
  across a generation change and assert the second carries the new one.
- **`claim_fn` verification is presence-only.** Atomicity comes from the existing
  `FOR UPDATE` inside one transaction, not from statement form. Stated rather than
  over-claimed.
- **The `tool_commit` rule matches any `<name>.commit()` under `tools/`.** All nine
  today are session commits. A future non-session `.commit()` would be a false
  positive — which fails loudly and costs one classified inventory line, the right
  way round for a gate.

## Changelog

**Revision 2** — after review. Changes:

- **`.commit()` is no longer treated as "semantic effect".** Detectors now find
  *candidates*; the inventory carries a human-declared `category`, and only
  `semantic` must fence. Three of the nine tool commits are `admission`, `cleanup`
  and `caller_fenced` — demanding a fence on cleanup would contradict spec §7, which
