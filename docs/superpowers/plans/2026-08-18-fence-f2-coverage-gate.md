# Fence F2 — Coverage Gate Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the mechanical gate that F3–F9 land against: an AST-derived inventory
of every belief-carrying effect site, locked against a checked-in file, plus a
verifier that each site marked fenced really is.

**Architecture:** Detectors find sites by AST and return `(kind, path, symbol)`
triples — no line numbers, which drift. A checked-in JSON inventory records every
site with `fenced: false` and the slice that will fence it. One test asserts the
derived set equals the file exactly, so a new unlisted effect site fails CI. A
second verifies every `fenced: true` entry. The detector logic is unit-tested
against synthetic source fixtures, so it is provable at F2 when nothing is fenced
yet.

**Tech Stack:** Python 3.12 stdlib `ast`, pytest. No database, no new dependency.

## Global Constraints

1. **F2 CONVERTS NO CALL SITES AND FENCES NOTHING.** Every inventory entry is
   `fenced: false` when this slice ends. F2 builds the instrument, not the fix.
2. **The inventory file is NEVER regenerated by the test.** Regeneration is a
   separate script a human runs deliberately. A test that regenerates and then
   compares to what it just generated always passes — that is the decorative-test
   trap in its purest form, and it would make every later slice's gate worthless.
3. **Site identity is `(kind, path, symbol)` — never a line number.** Line numbers
   drift on every unrelated edit and would make the gate a nuisance that people
   silence.
4. **Detector logic is tested against synthetic fixtures, not the live tree.**
   Asserting the detectors against real files only proves they agree with
   themselves today. Fixtures are what prove they will still bite in F5.
5. **A `fenced: true` entry must be verifiable at F2 even though no real site has
   it yet.** The verifier is proven against fixtures. If it can only be exercised
   in F3, it is untested code shipped as a safety mechanism.
6. `uv run ruff check .` is the gate — redirect to a log and read `$?`, never pipe
   into `tail`.
7. Fast test runs: `uv run pytest -n 16 --dist loadfile`. Never `-n auto`, never
   `--dist loadgroup`.
8. Never pipe a test or ruff command into `tail`/`head` — the pipeline exit status
   becomes the pager's. Use `cmd > /tmp/out.log 2>&1; echo "EXIT=$?"; tail -40 /tmp/out.log`.
9. pytest exits **4** on "no tests ran", so a path typo reads as success. Confirm a
   nonzero collected count.

### The classification rule you will need

`proposals/accepting.py:195` builds a `ToolContext` with `session_factory=None` and
the comment "unused on this path". It is a **request-driven** path that already holds
its own session — not belief-carrying. The same tool code is belief-carrying or not
depending on who built the ctx.

That settles a design question for F3 and the inventory must encode it: **the
generation is a property of the ctx, not of the tool.** A ctx with a generation
fences; a ctx without one is request-driven and uses plain liveness. So
`ToolContext` construction sites split into two kinds, and the gate must not demand
a stamp from the synthetic one.

### Task 1: AST detectors, proven against fixtures

**Files:**
- Create: `tests/fencing/__init__.py`, `tests/fencing/detectors.py`
- Test: `tests/fencing/test_detectors.py`

**Interfaces:**
- Produces:
  - `Site` — a `NamedTuple(kind: str, path: str, symbol: str)`, ordered and hashable.
  - `KIND_TOOL_COMMIT = "tool_commit"`, `KIND_CLAIM_FN = "claim_fn"`,
    `KIND_TOOL_CONTEXT = "tool_context"` — module-level constants.
  - `find_sites(source: str, path: str) -> set[Site]` — the single entry point. Takes
    source TEXT so it is testable without files.

**Detector rules** (implement exactly these; do not add more kinds):

- `tool_commit`: a call to `<name>.commit()` whose enclosing function is a
  module-level or nested `def`, in a file whose path contains
  `/proposal_assist/tools/`. `symbol` is the enclosing function's name. Multiple
  commits in one function collapse to ONE site — the unit is the function, because
  that is where a generation would be threaded.
- `claim_fn`: a module-level `def` whose name starts with `claim_next_` or
  `claim_queued_`, in a file under `/proposal_assist/`. `symbol` is the function
  name. (`claim_context_sha`, `claim_drift_hash`, `claim_sentence_around` are string
  helpers, not job claims — the `claim_next_`/`claim_queued_` prefixes exclude them.)
- `tool_context`: a call to `ToolContext(...)`. `symbol` is the enclosing function's
  name, or `"<module>"` at module level. A construction passing
  `session_factory=None` is **excluded** — it cannot originate a tool commit, so it
  carries no belief.

- [ ] **Step 3: Write the detectors**

Create `tests/fencing/detectors.py`:

```python
"""Fence F2 — AST detectors for belief-carrying effect sites.

Reads source as TEXT and imports nothing from `src/`. That is deliberate: a gate
that imports the code it watches can be disarmed by the same refactor it exists
to catch, and it could not be unit-tested against synthetic fixtures.

Site identity is (kind, path, symbol) — never a line number. Line numbers drift
on every unrelated edit, and a gate that fails for unrelated reasons is a gate
people learn to silence.
"""

from __future__ import annotations

import ast
from typing import NamedTuple

KIND_TOOL_COMMIT = "tool_commit"
KIND_CLAIM_FN = "claim_fn"
KIND_TOOL_CONTEXT = "tool_context"

_TOOLS_DIR = "/proposal_assist/tools/"
_PROPOSAL_ASSIST = "/proposal_assist/"
_CLAIM_PREFIXES = ("claim_next_", "claim_queued_")


class Site(NamedTuple):
    kind: str
    path: str
    symbol: str


def _enclosing(stack: list[str]) -> str:
    return stack[-1] if stack else "<module>"


def find_sites(source: str, path: str) -> set[Site]:
    """Every belief-carrying effect site in *source*, attributed to *path*.

    Pure: same inputs, same output, no filesystem access.
    """
    norm = path.replace("\\", "/")
    tree = ast.parse(source)
    sites: set[Site] = set()
    stack: list[str] = []

    def visit(node: ast.AST) -> None:
        pushed = False
        if isinstance(node, ast.FunctionDef | ast.AsyncFunctionDef):
            # claim functions: prefix-scoped so citations/'s claim_context_sha,
            # claim_drift_hash and claim_sentence_around (string helpers, not job
            # claims) are excluded.
            if _PROPOSAL_ASSIST in norm and node.name.startswith(_CLAIM_PREFIXES):
                sites.add(Site(KIND_CLAIM_FN, path, node.name))
            stack.append(node.name)
            pushed = True

        elif isinstance(node, ast.Call):
            func = node.func
            # <name>.commit() inside tools/ — attributed to the enclosing
            # function, so two commits in one function are ONE site: the function
            # is where a generation gets threaded.
            if (
                _TOOLS_DIR in norm
                and isinstance(func, ast.Attribute)
                and func.attr == "commit"
            ):
                sites.add(Site(KIND_TOOL_COMMIT, path, _enclosing(stack)))

            # ToolContext(...) — excluding constructions that pass
            # session_factory=None. Those cannot originate a tool commit (see
            # proposals/accepting.py, a request-driven path holding its own
            # session), so they carry no belief and must not be demanded a stamp.
            name = func.id if isinstance(func, ast.Name) else getattr(func, "attr", None)
            if name == "ToolContext":
                inert = any(
                    kw.arg == "session_factory"
                    and isinstance(kw.value, ast.Constant)
                    and kw.value.value is None
                    for kw in node.keywords
                )
                if not inert:
                    sites.add(Site(KIND_TOOL_CONTEXT, path, _enclosing(stack)))

        for child in ast.iter_child_nodes(node):
            visit(child)
        if pushed:
            stack.pop()

    visit(tree)
    return sites
```

- [ ] **Step 1: Write the regeneration script**

Create `tests/fencing/regenerate_inventory.py`:

```python
"""Regenerate fence_inventory.json from the current tree.

RUN THIS BY HAND, DELIBERATELY:

    uv run python -m tests.fencing.regenerate_inventory

NEVER call it from a test. A test that regenerates and then compares to what it
just generated always passes — it is a gate that cannot fail, which is worse than
no gate because every later slice would trust it (Global Constraint 2).

Existing `fenced` values are PRESERVED across a regeneration. Only added and
removed sites change. Losing the fenced flags would silently un-prove every slice
that came before.
"""

from __future__ import annotations

import json
import pathlib

from tests.fencing.detectors import KIND_CLAIM_FN, Site, find_sites

REPO = pathlib.Path(__file__).resolve().parents[2]
SRC = REPO / "src" / "call_manager"
INVENTORY = pathlib.Path(__file__).resolve().parent / "fence_inventory.json"

_SLICE_FOR_KIND = {KIND_CLAIM_FN: "F4"}
_DEFAULT_SLICE = "F3"


def scan_tree() -> set[Site]:
    """Every belief-carrying effect site under src/call_manager."""
    sites: set[Site] = set()
    for p in sorted(SRC.rglob("*.py")):
        if "__pycache__" in p.parts:
            continue
        rel = p.relative_to(REPO).as_posix()
        sites |= find_sites(p.read_text(encoding="utf-8"), rel)
    return sites


def main() -> None:
    previous = {}
    if INVENTORY.exists():
        for e in json.loads(INVENTORY.read_text(encoding="utf-8")):
            previous[(e["kind"], e["path"], e["symbol"])] = e["fenced"]

    rows = [
        {
            "kind": s.kind,
            "path": s.path,
            "symbol": s.symbol,
            "fenced": previous.get((s.kind, s.path, s.symbol), False),
            "slice": _SLICE_FOR_KIND.get(s.kind, _DEFAULT_SLICE),
        }
        for s in sorted(scan_tree())
    ]
    INVENTORY.write_text(json.dumps(rows, indent=2) + "\n", encoding="utf-8")
    print(f"wrote {len(rows)} sites to {INVENTORY}")


if __name__ == "__main__":
    main()
```

- [ ] **Step 3: Write the gate test**

Create `tests/fencing/test_fence_coverage.py`:

```python
"""Fence F2 — the coverage gate.

This is the instrument F3-F9 land against. It asserts two things:

  1. The set of belief-carrying effect sites in the tree EQUALS the checked-in
     inventory. A new committing tool, a new claim function or a new ToolContext
     construction fails CI until someone adds it and says which slice fences it.
  2. Every entry marked `fenced: true` really is fenced (Task 3).

At F2 every entry is `fenced: false`, so (2) has no live data — which is why the
verifier is proven against fixtures in test_detectors.py's sibling rather than
here. (1) does real work from the moment it lands.
"""

from __future__ import annotations

import json
import pathlib

from tests.fencing.detectors import Site
from tests.fencing.regenerate_inventory import INVENTORY, scan_tree


def load_inventory() -> list[dict]:
    return json.loads(pathlib.Path(INVENTORY).read_text(encoding="utf-8"))


def _as_sites(rows: list[dict]) -> set[Site]:
    return {Site(r["kind"], r["path"], r["symbol"]) for r in rows}


def test_the_inventory_matches_the_tree_exactly():
    """The lock. Drift in either direction fails."""
    found = scan_tree()
    recorded = _as_sites(load_inventory())

    unlisted = sorted(found - recorded)
    stale = sorted(recorded - found)

    assert not unlisted, (
        "NEW belief-carrying effect sites are not in fence_inventory.json:\n  "
        + "\n  ".join(f"{s.kind} {s.path}::{s.symbol}" for s in unlisted)
        + "\n\nAdd them with `uv run python -m tests.fencing.regenerate_inventory`, "
        "then set each entry's `slice` to the slice that will fence it. Do NOT "
        "mark anything `fenced: true` that is not actually fenced."
    )
    assert not stale, (
        "fence_inventory.json lists sites that no longer exist:\n  "
        + "\n  ".join(f"{s.kind} {s.path}::{s.symbol}" for s in stale)
        + "\n\nRegenerate. If a site was fenced and has now VANISHED, check it was "
        "not simply renamed — a rename reads as delete+add and silently drops the "
        "fenced flag."
    )


def test_every_entry_has_the_four_required_keys():
    for row in load_inventory():
        assert set(row) == {"kind", "path", "symbol", "fenced", "slice"}, (
            f"malformed inventory entry: {row}"
        )
        assert isinstance(row["fenced"], bool)


def test_no_entry_carries_a_line_number():
    """Global Constraint 3. Identity must survive unrelated edits."""
    for row in load_inventory():
        assert ":" not in row["symbol"], (
            f"{row['symbol']!r} looks like it encodes a line number; site "
            f"identity is (kind, path, symbol) only"
        )


def test_f2_fences_nothing():
    """Global Constraint 1. F2 builds the instrument, not the fix.

    DELETE THIS TEST in F3, in the same commit that flips the first entry — not
    before, and not as a drive-by 'it's failing' fix.
    """
    fenced = [r for r in load_inventory() if r["fenced"]]
    assert not fenced, (
        "F2 must fence nothing; these are marked fenced:\n  "
        + "\n  ".join(f"{r['kind']} {r['path']}::{r['symbol']}" for r in fenced)
    )

    F1's primitives exist and nothing uses them. F3 deletes this test in the
    commit that wires the first one.
    """
    import ast

    src_root = pathlib.Path(INVENTORY).resolve().parents[2] / "src" / "call_manager"
    offenders = []
```

```python
_FENCE_CALLS = frozenset(
    {"live_at_generation", "acquire_commit_mutex_at_generation"}
)


def function_fences(source: str, symbol: str) -> bool:
    """True if the function named *symbol* calls a fence primitive.

    Deliberately NOT counting:
      - `acquire_commit_mutex_live` — the LIVENESS check. Accepting it would mark
        every site fenced while all of them still carry the weaker guarantee that
        this whole architecture exists to replace.
      - `_still_at_generation` — the RETIREMENT predicate, which matches DELETED
        workspaces. It is the fence's opposite, not a weaker version of it.

    Attribution is per-function: a neighbour fencing does not fence this one.
    `symbol` "<module>" means module level.
    """
    tree = ast.parse(source)

    target: ast.AST | None = None
    if symbol == "<module>":
        target = tree
    else:
        for node in ast.walk(tree):
            if (
                isinstance(node, ast.FunctionDef | ast.AsyncFunctionDef)
                and node.name == symbol
            ):
                target = node
                break
    if target is None:
        return False

    for node in ast.walk(target):
        if isinstance(node, ast.Call):
            func = node.func
            name = func.id if isinstance(func, ast.Name) else getattr(func, "attr", None)
            if name in _FENCE_CALLS:
                return True
    return False
```

## What F2 deliberately leaves undone

- **Nothing is fenced.** Every inventory entry is `false`. F3 flips the first ones.
- **No production code changes.** F2 touches `tests/` only.
- **The inventory covers three kinds, not every effect in the spec.** Room writes,
  turn finalizers and pass-runner milestones are not AST-detectable by a rule this
  simple — "is this commit reached from a claim?" is not syntactically decidable.
  F5–F7 extend the detectors with kinds of their own, against fixtures, the same way.
  A gate that silently claimed full coverage would be worse than one with a stated
  boundary.
- **The per-turn re-stamp is NOT covered, and this is the important gap.** Spec §9
  asks the gate to assert that every `ToolContext` construction "stamps the
  generation per turn". F2 can see that a construction site exists; it cannot see
  whether the generation is re-stamped on every `send_turn`. That is a runtime
  property, and it is the highest-risk silent failure in the whole architecture —
  `registry.py:80` documents the identical trap for provenance, where a stamp
  missed once leaks the previous turn's value. **F3 must prove it with a runtime
  test** (drive two turns through one retained ctx across a generation change and
  assert the second carries the new one). Do not let the gate's existence be read
  as covering it.
- **The `tool_commit` rule matches any `<name>.commit()` under `tools/`.** Today
  all nine are session commits. A future non-session `.commit()` there would be a
  false positive — which fails loudly and costs one inventory line, the right way
  round for a gate. Not worth narrowing on speculation.
- **`test_f2_fences_nothing` must be deleted in F3**, in the same commit that flips
  the first entry — not before, and not as a drive-by fix when it starts failing.
